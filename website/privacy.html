Privacy

Pointframe Privacy Policy

This policy covers the Pointframe desktop app, the Pointframe CLI, the Pointframe MCP server, and this website. Pointframe is free and open source, needs no account, and keeps your screenshots, recordings, and text on your machine.

Data collection

The project never collects screenshots, recordings, OCR text, file names, or file paths. They stay on your machine under %LOCALAPPDATA%\Pointframe, apart from what you choose to send somewhere yourself. An MCP capture tool returns the image to your MCP client, which passes it to your model; pass includeImage: false to return metadata only. Upload & copy link in the desktop app sends one capture to the HTTPS destination you configured.

Usage telemetry of the CLI and the MCP server

Official release builds of the CLI and the MCP server send one anonymous event per MCP tool call or CLI command to Azure Application Insights (from this version, a scenario's wait for the app to exit before a restart counts as one call). The event holds only these fixed values:

  • name: the MCP tool or CLI command, taken from a fixed list; any other value is reported as other.
  • outcome: success, error, cancelled, denied, verification_failed (a verification that ran and reported a failing or not-fresh result), or invalid_request (the call was rejected as malformed or invalid input). Error text is never sent.
  • duration_bucket: lt_1s, 1_5s, 5_30s, or gt_30s.
  • host: cli or mcp.
  • client (MCP only): claude-desktop, claude-code, codex, vscode, cursor, or other, mapped from the client name in the MCP initialize request.
  • version: the Pointframe version.
  • agent_install_id: a random ID created on first use and stored in %LOCALAPPDATA%\Pointframe\agent-install-id, shared by the CLI and the MCP server on that Windows account. It is not tied to your name, account, or machine.

No arguments, paths, screenshots, text, error messages, user names, or machine names are sent, and the exporter identifies itself only with the fixed names Pointframe.Cli or Pointframe.Mcp. The random install ID lets the project count how many installs use the CLI and the MCP server and whether they come back. Opting out deletes it, so opting back in starts a new, unrelated ID. Source builds send nothing, because the connection string is injected only by the official release pipeline.

The first run prints a one-time notice to standard error. The MCP server never writes to standard output outside the MCP protocol, so it also places the notice in its server instructions once. A small local file under %LOCALAPPDATA%\Pointframe records that the notice was shown.

Opting out of CLI and MCP telemetry

Set the environment variable POINTFRAME_TELEMETRY_OPTOUT=1 or the standard DO_NOT_TRACK=1, or create %LOCALAPPDATA%\Pointframe\agent-telemetry.json containing {"optOut": true}. A config file that cannot be read counts as an opt-out. When you opt out, no telemetry request is made at all. Telemetry never blocks a tool call or command, and a failure to send it is ignored.

Desktop app telemetry

Official installer builds of the desktop app send the usage telemetry described in the PRIVACY.md, including a random install ID that is not tied to an account. The desktop app has no in-app telemetry switch, and the opt-out above applies to the CLI and the MCP server only.

This website

The pages of this website at dimitar-radenkov.github.io/Pointframe, except the Screen Explainer pages, load a small script that measures how the site is used. It sends these data to Azure Application Insights:

  • Page views are recorded with the Application Insights JavaScript SDK's standard page-view and page-load timing data; see Microsoft's documentation. Because the site turns off the library's cookies and storage, the random identifiers the library attaches to each page view are created anew on every page load and cannot link one visit to the next.
  • The event website_session_started, sent once per browser tab session, with the referring page and the browser's user agent.
  • The event website_cta_clicked, sent when you click a tracked button or link such as Download, with the button's type and location on the page and the address it links to.
  • The events winget_command_copied and winget_command_copy_failed, sent when you use the copy button for the install command, with the package manager and the command shown.
  • The page path and address, a timestamp, and the UTM campaign parameters (utm_source, utm_medium, utm_campaign, utm_content, utm_term) when the address you arrived on carries them.

The site configures the analytics library not to set cookies and not to use browser storage, and the site's own code sets no cookies and writes nothing to local storage. The only thing the site's own code keeps in the browser is, in the tab's session storage, a random session ID created by your browser, a marker that this tab's visit was already counted, and, when the address you arrived on carries UTM parameters, the attribution of the visit (those UTM parameters, the landing page path, the time it was first seen, and the referring page); the browser deletes them when the tab closes. The session ID is not tied to your name or account and lets the project count how many visits it sees. An earlier version of the site kept an event log and campaign parameters in local storage; the site now deletes those two entries when you visit.

These data go to the same Application Insights resource as the telemetry above, under the Third-party sharing and Retention terms below. The Screen Explainer pages load no scripts. To avoid website measurement, block scripts for this site or use a tracker blocker; the site works without them.

Third-party sharing

Telemetry goes to Microsoft Azure Application Insights, which acts as a processor on the project's behalf. Application Insights receives the IP address of the connection, derives a coarse country and city from it, and stores the address masked (IP masking is on). The exporter attaches no host name, user name, or other machine details. Nothing is sold or shared with anyone else.

Retention

Telemetry is kept in the project's Application Insights resource under its default retention of 90 days, unless the maintainer changes that setting, and is used only to see which tools and commands are used and whether they fail, and how visitors use this website. Files on your machine stay until you delete them.

Contact

Questions, deletion requests, and privacy concerns: open an issue at github.com/dimitar-radenkov/Pointframe/issues. The same policy is in the PRIVACY.md.

pointframe verify for Claude Code and Codex on Windows

Make your coding agent prove it's done

Coding agents often say "done" without evidence. pointframe verify runs your project's own build and test commands and writes a verdict. A Stop hook then keeps Claude Code or Codex working until the last verdict is a fresh pass on the files as they are now.

Download the CLI Set it up in your project

The problem: "done" without evidence

An agent that edits code can end its turn with a confident summary while the build is broken or a test fails. You find out later, in review or in CI. What you want is a rule the agent cannot talk its way around: the work is finished only when your own checks pass on the current files.

How it works

  • Your own checks. The spec in .pointframe/verify.json lists gates, which are commands you already run. For a .NET solution these are dotnet build and dotnet test; for a Node project they are your npm scripts.
  • A verdict tied to the files. A pass is tied to the exact files in your working tree. Change a file and the pass is no longer fresh.
  • A Stop hook. When the agent tries to stop without a fresh pass, the hook runs the checks. If they fail, it blocks the stop and tells the agent what failed.
  • Optional desktop evidence. If your project is a Windows desktop app, the spec can also hold scenarios that drive the running app and produce signed evidence. They are optional and not needed for build and test checks.

What it looks like

A real trial: the agent was asked for a small change, and the checks failed when it tried to finish. The hook blocked the stop and passed the failure back.

Pointframe verify failed (block 1 of 5), so this work is not done yet.
...
error CS0117: 'MathOps' does not contain a definition for 'Divide'

The agent added Divide and tried to finish again. The hook ran the checks, they passed, and the stop was allowed. Then:

pointframe verify status
...
"status": "pass",
"fresh": true

The ellipses mark output left out here. fresh: true means the pass was made on the files as they are now.

Install and set up

Download Pointframe.Cli-<version>-win-x64.zip and its .sha256 file from the latest release, check the hash, extract the ZIP, and from that folder run:

.\Pointframe.Cli.exe install

This copies the CLI to %LOCALAPPDATA%\Programs\Pointframe.Cli and adds it to your user Path. Open a new terminal and restart your agent so it sees the new Path. The winget package DimitarRadenkov.Pointframe.Cli is awaiting acceptance; until it appears in winget search, use the ZIP.

Then, from your project root:

pointframe verify init
pointframe verify run
pointframe verify status

verify init detects your gates and writes the spec plus a Stop hook for Claude Code and Codex. Existing settings are kept, and running it again is safe. Commit .pointframe/verify.json and the hook files so the whole team gets them. Standard commands such as dotnet build and npm test are approved automatically; for anything else you approve the commands once with pointframe verify trust.

Run it in CI too

The hook is a local safety net. It can be absent on a fresh clone, skipped, or used up after five blocks. A CI job is the check nobody can skip. The guide has a ready workflow that downloads a pinned CLI release, checks its hash, and verifies the repository; see Run in CI.

Honest limits

  • It does not prove your code is correct. It proves that your own checks pass on the current files.
  • It runs on Windows x64, and the toolchain your checks call must already be installed.
  • Stopped is not verified. The hook blocks a failing stop at most five times in a session. After that the agent may stop, and the message says the work was NOT verified. The agent may also stop with that message when only a person can fix the problem, such as an untrusted or invalid spec.
  • Before you trust "done", run pointframe verify status and look for "status": "pass" and "fresh": true. For a project that matters, require a pass in CI as well.

Frequently asked questions

Does a passing verdict prove my code is correct?

No. It proves that your own checks, such as dotnet build and dotnet test or your npm scripts, pass on the exact files in your working tree.

Does the agent always stay blocked until the checks pass?

No. The hook blocks a failing stop at most five times in a session. After that the agent may stop, and the message says the work was not verified.

Which platforms and agents does it support?

Windows x64, with a Stop hook for Claude Code and for Codex. The toolchain your checks call must already be installed.

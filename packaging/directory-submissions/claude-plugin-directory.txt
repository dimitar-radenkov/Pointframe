Expected review notes
  The plugin starts a local stdio MCP server with `.mcp.json` command `${CLAUDE_PLUGIN_ROOT}/scripts/start-mcp.cmd` and no arguments. That two-line launcher runs `powershell.exe -NoProfile -ExecutionPolicy Bypass -File start-mcp.ps1`, passes its arguments through, and returns the exit code; the execution-policy bypass covers only that process. The script is a non-shell file in a subfolder, so the scan may hold it for a reviewer ("Scripts the validator couldn't follow"). It downloads one pinned release asset from github.com/dimitar-radenkov/Pointframe, verifies its SHA-256 against server.lock.json, caches it, and runs it. The README states all of this. The downloaded executable is a compiled binary built by the repository's public CD pipeline from the same source tree; the SHA-256 is also published beside the release asset.

Data handling answers
  Does the plugin read or store personal data? It can capture the user's screen when the user asks Claude to. Screenshots, OCR text, and recordings are stored only on the user's disk under %LOCALAPPDATA%\Pointframe. A screenshot reaches the model only when a capture tool returns it to the client; includeImage false returns metadata only. Nothing is uploaded by the plugin.
  Does it send data to services other than its declared connectors? Official builds of the MCP server send one anonymous usage event per tool call (tool name, outcome, duration bucket, host, MCP client type, version) to Azure Application Insights with IP masking. No arguments, paths, screenshots, text, error messages, or identifiers. Opt out with POINTFRAME_TELEMETRY_OPTOUT=1 or DO_NOT_TRACK=1. The first start also downloads the server from GitHub Releases.
  How long is data kept? Locally, until the user deletes it. Telemetry follows the retention in the privacy policy.
  Is it intended for people under 18? No (CONFIRM wording).
